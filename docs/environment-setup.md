# Environment setup

Every `.env` value that needs an outside account, and where it comes from. `.env` is never committed; production
values live in `fahim/deployment/server-env/` on bloodykheeng's PC (outside every repo).

## Database

MySQL 8, database `kheengz` (`utf8mb4_unicode_ci`), user `root` with no password locally (Laragon).

## Firebase (push notifications)

Two projects in the Firebase console, both under bloodykheeng's Google account:

| Environment | Project id | Service account JSON (kept in `fahim/deployment/firebase/`) |
| --- | --- | --- |
| Development | `kheengz-dev` | `kheengz-dev-firebase-adminsdk-fbsvc-c12545e141.json` |
| Production | `kheengz-6f97b` | `kheengz-6f97b-firebase-adminsdk-fbsvc-c09363130d.json` |

- The JSON's fields go into `FIREBASE_*` (one line each; `FIREBASE_PRIVATE_KEY` as ONE double-quoted line with
  `\n`), read by `config/services.php` → `services.firebase`, never by `env()` in app code, so
  `config:cache` keeps working. The production block is ready in
  `fahim/deployment/server-env/kheengz-laravel.production.firebase.env`.
- The Next app uses the **same project** per environment (`NEXT_PUBLIC_FIREBASE_*`).
- Check a key works without sending anything (a validate-only message to a topic):

  ```bash
  php artisan tinker --execute '$m = (new Kreait\Firebase\Factory)->withServiceAccount(config("services.firebase"))->createMessaging(); print_r($m->validate(Kreait\Firebase\Messaging\CloudMessage::new()->withNotification(["title"=>"check","body"=>"check"])->toTopic("kheengz-setup-check")));'
  ```

  Both projects passed this on 15 Nov 2026.
- Web push in the browser is optional and not in the MVP (workspace D18), so `NEXT_PUBLIC_FIREBASE_VAPIDKEY`
  stays empty. If it is wanted later: Project settings > Cloud Messaging > Web Push certificates.
